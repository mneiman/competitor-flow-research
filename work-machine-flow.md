# Run the competitor flow and data exercise

Use the accompanying `competitor-research-prompt.md`. It preserves the specific research brief and the later map/data-organization refinement. It is not replaced with a generic prompt.

## Before starting

Open an employer-approved AI tool and an approved private working folder. The public prompt file can be read without a GitHub account; the AI tool may still require its own login. Do not sign into a personal AI account or upload company material unless employer policy permits it.

Use public evidence and fictional examples first. Keep credentials, customer records, internal documents and proprietary system details out of public services unless explicitly authorized.

## First session

1. Copy the research brief and later refinement into the approved tool. Replace project names locally if needed. Explain that output belongs in your approved private folder, not the public prompt repository.
2. Begin with one competitor and one use case: counter sale or requesting parts for a repair-order job. Check the quality before expanding to all ten products.
3. Ask for a source register: source URL, date/version, product/region, what was observed, and limitations. Keep documented behavior, vendor claims, user reports, inference, proposals and unknowns separate.
4. Ask for a complete flow: actor, trigger, decisions, quantities/units, state changes, handoffs and exceptions. Seeing a UI control does not establish its transaction behavior.
5. Build a small branching question map. Follow the answer into the next question instead of filling in the same fixed template repeatedly.
6. Map the evidence to candidate data concepts and relationships. Ask which rule motivates each concept, who owns it, how identity carries across systems, and which facts remain unverified. Do not accept an authoritative table count without schema and rule evidence.
7. Challenge the proposal with competing requests for the last unit, partial receipt, cancellation after receipt, substitution, unused return and a duplicate scan. Mark all invented examples.

## Expand and save

Compare the remaining products using the same evidence standard. Keep one dossier per product, a cross-product comparison, linked maps, editable diagram source, a conceptual data model and validation questions. Vendor behavior is an input to questions, not proof of your own deployment.

Save outputs in an approved private repository or folder. Review every diff before committing. Never copy the whole working directory into the public prompt repository. Ask authorized internal experts to validate unresolved legacy rules before implementing them.

## End the session

Save `handoff.md` with scope, source dates, confirmed findings, proposals, decisions, unresolved questions, changed files and the exact next exercise. Distinguish saved work from drafts.

Next session: open the same approved private work files, read the handoff, check for newer evidence, and continue without repeating completed research. The public copy carries the prompt and method only, not your private research history.
